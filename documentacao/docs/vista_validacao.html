Validação de uma instância

O resultado de validar uma instância concreta de um HLM contra as regras do grafo, no cenário de um perfil: a projeção diz que propriedades são obrigatórias ou permitidas, o perfil fixa valores e contextos externos, e cada regra é avaliada em cada ocorrência do nó onde vive.

CampoValor
Páginavalidacao_<exemplo> (na aplicação web: separador Validação)
ViewModelvalidacao
Para que serveConfirmar que as regras declaradas fazem o que se pretende com dados reais, e ver porque uma instância é rejeitada: que regra falha, em que ocorrência e com que valor.
Exemplovalidacao_fatura_at_com_erros.html (estática) · na aplicação: /vistas/validacao_fatura_at_com_erros.html

Dados que agrega

  • o cenário: HLM, perfil, projeção, valores fixados e contextos externos (com a origem de cada um: perfil, pedido ou omissão)
  • os problemas estruturais da instância: obrigatórias em falta, propriedades excluídas pela projeção, chaves desconhecidas, tipos e cardinalidades errados, valores que contradizem o perfil
  • cada regra em cada ocorrência concreta (uma linha de fatura, a morada do emitente e a do cliente), com o estado, os termos da condição avaliados, o valor lido e a mensagem
  • as conclusões das RIC que se aplicam
  • a instância avaliada, já com os valores fixados pelo perfil

Como usar

  • Na aplicação web, no separador Validação: escolher um exemplo ou colar a instância (JSON com a forma do HLM: papéis das composições e nomes das propriedades; as composições repetíveis são listas), escolher o perfil (ou só o HLM) e indicar os contextos externos.
  • Ler primeiro o resultado e a estrutura; depois as regras não conformes, as conclusões e as não avaliáveis.
  • As caixas no topo das regras mostram ou escondem cada estado (por omissão, os conformes, os não aplicáveis, os ausentes e os fora da projeção estão escondidos).
  • Pela linha de comandos: python -m ecv validar <instancia.json | exemplo> [--perfil P | --hlm H] [--contexto k=v ...]; termina com 1 se a instância for inválida.
  • Resultado: válida quando não há problemas estruturais nem regras não conformes.
  • Estados por regra e ocorrência: não conforme, conforme, conclusão, não aplicável, sem valor, não avaliável, fora da projeção, ausente.
  • Contextos externos: a origem de cada valor; instância avaliada: o JSON depois dos valores fixados pelo perfil.

validacao: Validação de uma instância

  • Pergunta. A instância cumpre as regras do HLM no cenário do perfil (estrutura, conformidade e conclusões)?
  • Parâmetros. exemplo (uma instância de validacao/exemplos), ou instancia com perfil ou hlm; contextos opcional.
  • Operação. O motor de [validacao/](../../validacao/README.md): o cenário do perfil (USA, PROJETA, OBRIGATORIA, PERMITIDA, FIXA), a árvore do HLM e, para cada regra em cada ocorrência concreta da instância, a condição (TERMO, CHAMA) e a restrição (RESTRINGE, CHAMA) avaliadas sobre os valores da instância.
  • Estados. não conforme, conforme, conclusão, não aplicável, sem valor, não avaliável, fora da projeção, ausente.
  • JSON. instancia, descricaoInstancia, hlm, perfil, projecao, valida, fixados[] {caminho, valor}, contextos[] {nome, valor, origem}, resumo {estado: n}, estrutura[] {tipo, caminho, problema}, resumoEstrutura, conclusoes[], regras[] {regra, tipo, descricao, vive, ocorrencia, estado, termos[{texto, valor, resultado}], valor, detalhe, mensagem, conclusao}, instanciaAvaliada.
  • Cypher. validacao.cypher (o cenário e, por ocorrência, cada regra com a restrição e os termos; a avaliação sobre os valores da instância está no Python).

Consulta Cypher equivalente (validacao.cypher)

// ViewModel 'validacao' — o cenário e as regras que o motor avalia sobre uma instância.
// Parâmetros: $perfil (ex.: "AuditoriaSetembro2026").
// A avaliação sobre os valores da instância (estrutura, termos, restrições, funções) está em validacao/motor.py;
// esta consulta devolve o que o motor lê do grafo: a projeção, os valores fixados e, por ocorrência, cada regra
// com a restrição e os termos da condição.
MATCH (pf:Perfil {nome: $perfil})-[:USA]->(pj:Projecao)-[:PROJETA]->(h:HLM)
OPTIONAL MATCH (pf)-[f:FIXA]->(alvo)
WITH pf, pj, h, collect({caminho: f.caminho, contexto: CASE WHEN alvo:ContextoExterno THEN alvo.nome END, valor: f.valor}) AS fixados
OPTIONAL MATCH (pj)-[o:OBRIGATORIA]->()
WITH pf, pj, h, fixados, collect(o.caminho) AS obrigatorias
OPTIONAL MATCH (pj)-[p:PERMITIDA]->()
WITH pf, pj, h, fixados, obrigatorias, collect(p.caminho) AS permitidas
MATCH caminho = (h)-[:COMPOSTO_POR*0..4]->(m)
WITH pf, pj, h, fixados, obrigatorias, permitidas, m,
     reduce(s = '', r IN relationships(caminho) | s + CASE s WHEN '' THEN '' ELSE '.' END + r.papel) AS ocorrencia
OPTIONAL MATCH (m)-[:CONTEM]->(prop:Propriedade)
WITH pf, pj, h, fixados, obrigatorias, permitidas, ocorrencia, m, collect(prop) AS props
UNWIND [m] + props AS no
MATCH (r:Regra)-[:ASSOCIADA_A]->(no)
OPTIONAL MATCH (r)-[:RESTRITA_POR]->(rs:Restricao)
OPTIONAL MATCH (rs)-[re:RESTRINGE]->()
OPTIONAL MATCH (rs)-[rc:CHAMA]->(fr:Funcao)
OPTIONAL MATCH (r)-[:CONDICIONADA_POR]->(c:CondicaoAplicabilidade)
OPTIONAL MATCH (c)-[t:TERMO]->()
OPTIONAL MATCH (c)-[tc:CHAMA]->(ft:Funcao)
RETURN pf.nome AS perfil, pj.nome AS projecao, h.nome AS hlm, fixados, obrigatorias, permitidas,
       ocorrencia, r.id AS regra, labels(r) AS tipo,
       coalesce(re.texto, rc.chamada) AS restricao, coalesce(re.caminho, rc.argumentos) AS lidoPelaRestricao,
       [x IN collect(DISTINCT {texto: t.texto, caminho: t.caminho, operador: t.operador, valor: t.valor, contexto: t.contexto})
        WHERE x.texto IS NOT NULL]
       + [x IN collect(DISTINCT {texto: tc.chamada, argumentos: tc.argumentos}) WHERE x.texto IS NOT NULL] AS termos
ORDER BY ocorrencia, regra;
