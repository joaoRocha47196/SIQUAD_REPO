ecv/6_validation/__init__.py

6 · Validation: evaluates a concrete instance of a HLM against the rules of the graph, in the scenario
of a profile.

Receives: the graph (memory or Neo4j), an instance (JSON with the shape of the HLM), a profile (or a
HLM) and the values of the external contexts.
Needs: an implementation of every function the rules call (functions/).
Produces: the ViewModel 'validacao' (structure problems, the state of each rule in each occurrence,
the conclusions).

    engine.py       validate(): scenario -> structure -> rules -> result
    scenario.py     the profile's projection, fixed values and contexts
    structure.py    structural checks of the instance
    rules.py        evaluation of RP, RIR and RIC per occurrence
    instance.py     navigation in the instance, base types
    functions/      implementations of the declared functions (registry by decorator)
    examples/       example instances: {descricao, perfil | hlm, contextos, instancia}
    test_instances.py  test instances of a domain: skeleton from the structure and profile, request to the LLM, saved and validated

ecv/6_validation/engine.py

The validation engine: evaluates one instance of a HLM against the rules of the graph, in the scenario
of a profile, and returns the ViewModel 'validacao'.

    1. Scenario   (scenario.py)   the profile's projection, fixed values and contexts
    2. Structure  (structure.py)  fixed values applied; unknown keys, types, cardinalities, mandatory paths
    3. Rules      (rules.py)      each rule in each concrete occurrence: condition, restriction, conclusion
    4. Result                     valid when there are no structural problems and no non-conforming rule

ecv/6_validation/functions/__init__.py

Implementations of the functions declared in ECV declarations.

A function is declared in the declaration (name, parameters, external contexts, "Verdadeira quando…")
and called, structurally, by the rules; the engine needs to know how to run it. Each module of this
package implements a family of functions and registers each one under its declared name:

    @implements("naoPosteriorAHoje")
    def not_after_today(date, *, contexts): ...

An implementation receives the arguments in parameter order and the external contexts as a dict, and
returns True (holds) or False; it raises Unavailable when a value or a context is missing. A declared
function without an implementation makes the rules that call it 'não avaliável'.

Adding a function = adding a decorated function to one of these modules (or a new module here): the
package loads every module it contains.
DefiniçãoDescrição (docstring)

def load(reload)Import every module of this package (each registers its functions). With reload, re-read them from disk.

ecv/6_validation/rules.py

Evaluation of the rules (RP, RIR, RIC) of the HLM on an instance, in each concrete occurrence of the
node where each rule lives (the issuer's address and the client's; every invoice line).

States of a rule in one occurrence:
  não conforme      the condition holds (or it is an RP) and the restriction fails
  conforme          the condition holds (or it is an RP) and the restriction is met
  conclusão         an RIC whose condition holds
  não aplicável     the condition does not hold (or reads a value the instance does not carry)
  sem valor         the restriction targets a property the instance does not carry (mandatoriness is the projection's)
  não avaliável     an external context or a function implementation is missing, or a term is outside the projection
  fora da projeção  the restriction reads a property the projection does not include (nor the profile fixes),
                    or the node where the rule lives is entirely outside the projection
  ausente           the node where the rule lives is not in the instance (and the projection includes it)
