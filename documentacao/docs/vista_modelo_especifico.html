Vista de um modelo específico (SM ou USM)

Um SM ou um USM visto por si: primeiro, por quem é usado (os caminhos de composição desde cada HLM); depois, a sua árvore de dependências até às folhas, em que cada SM ou USM indica que HLM o usam; por fim, a tabela com a estrutura, a descrição das propriedades e as regras que vivem no modelo e nas suas propriedades.

CampoValor
Páginasm_<SM> | usm_<USM>
ViewModelmodelo (nivel=SM|USM, regras=true)
Para que servePerceber o efeito de mexer num modelo partilhado: em que HLM aparece, por que papéis, e que regras leva consigo.
Exemplousm_Morada.html (estática) · na aplicação: /vistas/usm_Morada.html

Dados que agrega

  • os caminhos de composição de cada HLM até ao modelo (com papel e cardinalidade)
  • a subárvore do modelo até às propriedades
  • os HLM que usam cada SM e USM da subárvore
  • as regras que vivem no modelo e abaixo dele (definidas uma vez, válidas em todos os HLM que o usam)

Como usar

  • Clicar em qualquer modelo (no topo, na árvore ou na tabela) para navegar para ele.
  • Abrir 'usado por' numa caixa da árvore para ver os HLM que usam esse SM ou USM.
  • Usar os mesmos controlos da vista com regras (atributos e agrupamento).
  • Usado por: caminhos desde cada HLM.
  • Árvore até às folhas; os mesmos controlos da vista com regras.

ViewModel modelo

Pergunta: Qual é a estrutura de um modelo até às folhas, quem o usa e (com regras) que regras vivem em cada nó?
Parâmetros: nivel, nome, regras?
Percurso no grafo: (modelo)-COMPOSTO_POR*->(SM|USM)-CONTEM->(Propriedade); com regras: (Regra)-ASSOCIADA_A->(nó), Regra-RESTRITA_POR->Restricao-RESTRINGE|CHAMA->, Regra-CONDICIONADA_POR->Condicao-TERMO|CHAMA->; para cima: COMPOSTO_POR inverso até aos HLM; Projecao-PROJETA->HLM.

modelo: Vista de um modelo (HLM, com regras, específico)

  • Pergunta. Qual é a estrutura de um modelo até às folhas, quem o usa e (com regras) que regras vivem em cada nó?
  • Vistas. hlm_<HLM> (nivel=HLM), regras_<HLM> (nivel=HLM, regras=true), sm_<SM> e usm_<USM> (nivel=SM|USM, regras=true). Substitui as antigas vistas ECM, estrutural, global, alcance, reutilização e "RIC, funções e contextos".
  • Parâmetros. nivel, nome, regras (opcional).
  • Operação sobre o grafo.
    1. (raiz)-[:COMPOSTO_POR*]->(SM|USM), pela ordem, com papel e cardinalidade; -[:CONTEM]->(Propriedade).
    2. Fatores discriminantes: propriedades com <-[:TERMO]-, ou <-[:LE {parte: termo}]-.
    3. Num HLM: <-[:PROJETA]-(Projecao)<-[:USA]-(Perfil).
    4. Num SM ou USM: <-[:COMPOSTO_POR]- até aos HLM (os caminhos de quem o usa), e o mesmo para cada SM e USM da subárvore.
    5. Com regras: em cada nó, <-[:ASSOCIADA_A]-(Regra); de cada regra, -[:RESTRITA_POR]->(Restricao)-[:RESTRINGE|CHAMA]->, -[:CONDICIONADA_POR]->(Condicao)-[:TERMO|CHAMA]->, e (Funcao)-[:LE {regra}]->. As RIR agrupam-se pela propriedade que restringem, com a indicação de haver vista de decisão (≥ decisaoMinimoRIR).
    6. Com regras: as funções chamadas (-[:DEPENDE_DE]->) e os contextos externos (<-[:FIXA]-(Perfil)).
  • JSON. arvore (aninhada: nivel, nome, papel, cardinalidade, propriedades[], filhos[], usadoPor[]); blocos[] = {nome, nivel, linhas[], resumoPropriedades[]} (um por composição direta), cada linha com regras[] (fichas) e rir[] = {alvo, nome, regras[], decisao}; projecoes[]; usadoPor = {hlm[], caminhos[]}; com regras, regras[] (todas as fichas), contagem, funcoes[], contextos[].
  • Cypher. modelo.cypher (árvore, quem usa, projeções) e regras_modelo.cypher (regras por nó, com os campos separados).

Consulta Cypher equivalente (modelo.cypher)

// ViewModel 'modelo' — a árvore de um modelo (HLM, SM ou USM) até às folhas, e quem o usa.
// Parâmetros: $nivel ("HLM", "SM" ou "USM"), $nome (ex.: "Dispositivo", "Cliente", "Morada").

// 1. Árvore: cada modelo alcançado por COMPOSTO_POR, com o caminho (papéis), a cardinalidade e as propriedades
MATCH (raiz {nome: $nome}) WHERE $nivel IN labels(raiz)
MATCH caminho = (raiz)-[:COMPOSTO_POR*0..]->(m)
WITH m, relationships(caminho) AS rs
WITH m, reduce(s = '', r IN rs | s + CASE s WHEN '' THEN '' ELSE '.' END + r.papel) AS caminho,
     CASE size(rs) WHEN 0 THEN null ELSE last(rs).cardinalidade END AS cardinalidade
OPTIONAL MATCH (m)-[c:CONTEM]->(p:Propriedade)
WITH m, caminho, cardinalidade, p, c ORDER BY c.ordem
RETURN caminho, labels(m)[0] AS nivel, m.nome AS modelo, cardinalidade, m.descricao AS descricao,
       [x IN collect(p) | {nome: x.nome, tipo: x.tipo, descricao: x.descricao}] AS propriedades
ORDER BY caminho;

// 2. Quem usa o modelo: os caminhos de composição desde cada HLM (vazio para um HLM)
MATCH (raiz {nome: $nome}) WHERE $nivel IN labels(raiz)
MATCH caminho = (h:HLM)-[:COMPOSTO_POR*1..]->(raiz)
RETURN h.nome AS hlm, [n IN nodes(caminho) | n.nome] AS modelos, [r IN relationships(caminho) | r.papel] AS papeis
ORDER BY hlm;

// 3. Projeções (só para um HLM)
MATCH (raiz:HLM {nome: $nome})<-[:PROJETA]-(pj:Projecao)
OPTIONAL MATCH (pf:Perfil)-[:USA]->(pj)
RETURN pj.nome AS projecao, pj.descricao AS descricao, collect(pf.nome) AS perfis
ORDER BY projecao;
