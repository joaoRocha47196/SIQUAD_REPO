README do repositório

Implementação de referência da Estratificação do Conhecimento de Validação (ECV): a especificação de cada entidade da ECM (HLM, SM, USM, propriedades, composições) e da ECR (projeções, RP, RIR, RIC, restrições, condições, funções, contextos externos, perfis), a Declaração ECV e as declarações de exemplo; a transformação de dados de origem em declarações; a ingestão num grafo único; as vistas; a validação de instâncias; e a aplicação web que dá acesso a tudo.

Módulos

PastaRecebeProduz
ecv/0_transformerficheiros de origem em formatos conhecidos (incluindo texto em linguagem natural)um inventário por fonte; pedidos ao LLM de adaptadores para formatos novos
ecv/1_ecv_builderos inventários de um domínio e a especificação internaas declarações completas, num pedido de geração ao LLM, revistas por camadas (A a F)
ecv/2_amendmentsoperações (de uma resposta do LLM, de um formulário, de uma tabela CSV)as declarações alteradas de forma consistente
ecv/3_ingestiondeclaraçõeso grafo integrado, verificado e sem duplicados
ecv/4_grapho grafoo armazenamento (memória ou Neo4j) e a base de dados da aplicação
ecv/5_viewso grafo e uma vistao ViewModel (JSON) e a página HTML
ecv/6_validationo grafo, uma instância e um perfilo resultado da validação de cada regra em cada ocorrência; instâncias de teste a partir da estrutura e do perfil
ecv/7_webapppedidos HTTPas páginas e a API para todas as operações

Apoio: ecv/config (a configuração única, ecv.config.json), ecv/shared (área de trabalho dos domínios, pedidos ao LLM), ecv/tools (documentação). Fora do código: specs/ (a especificação), dominios/ (os domínios: fontes, inventários, declarações, mapeamento, pedidos), pedidos/ (pedidos de implementação de funções), documentacao/ (a documentação técnica e as vistas estáticas), dados_teste/ (tabelas CSV, pedidos em linguagem natural e a descrição de um domínio para experimentar), tests/.

Os ficheiros são a fonte de verdade. O grafo é derivado deles pela ingestão e é o que as vistas, a validação e a pesquisa consultam.

Instalação e uso

Python 3.10 ou superior; o núcleo só usa a biblioteca padrão. requirements.txt tem os pacotes opcionais (jsonschema, neo4j).

cd ecv_referencia
pip install -r requirements.txt
python -m unittest discover -s tests -t .
python -m ecv servidor                     # aplicação web em http://127.0.0.1:8000
python -m ecv servidor --neo4j             # com o Neo4j como base de dados

Neo4j: docker run -d --name ecv-neo4j -p 7474:7474 -p 7687:7687 -e NEO4J_AUTH=neo4j/ecvreferencia neo4j:5.26-community.

A linha de comandos (python -m ecv --help) faz as mesmas operações que a aplicação web.

Na aplicação, o trabalho de um domínio segue os separadores: Início (criar o domínio) › Declaração (1. Extração: documentos e adaptadores; 2. Geração: o pedido ao LLM) › Alterações (revisão por camadas A a F) › Vistas › Instâncias e Validação. Cada página indica onde está, no código e nos ficheiros, o que mostra e o que altera.

Documentação

documentacao/site/index.html (gerada com python -m ecv documentacao): o sistema e os módulos, as specs, a transformação (o esquema de prompting da geração, a revisão por camadas, os pedidos ao LLM, as alterações), a ingestão, o grafo e a base de dados, as vistas, a aplicação web e o código. As vistas das declarações de exemplo estão em documentacao/vistas/index.html (python -m ecv vistas).
