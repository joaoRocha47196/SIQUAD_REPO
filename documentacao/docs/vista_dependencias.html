Análise de dependência de validade

O que muda na validação quando uma propriedade toma cada um dos seus valores: para cada valor (dos plausíveis e dos usados nos termos), as regras cuja condição de aplicabilidade passa a verificar-se, a condição completa com o termo sobre esta propriedade em destaque, a restrição ou conclusão de cada regra e as propriedades afetadas. Lê-se como um fluxo: propriedade → valor → condição → regras → propriedades afetadas.

Para que servePerceber de que depende a validade das outras propriedades; prever o efeito de um valor antes de o fixar num perfil.
Exemplodependencias_Identificacao_tipoDispositivo.html (estática) · na aplicação: /vistas/dependencias_Identificacao_tipoDispositivo.html

Dados que agrega

  • a propriedade, a sua descrição e as RP com os valores plausíveis
  • para cada valor: as regras que se aplicam e as propriedades que elas restringem
  • para cada regra: todos os termos da condição (o desta propriedade em destaque), a restrição, a mensagem e a conclusão
  • as regras cujo termo sobre a propriedade não é de seleção (gamas, contextos, funções)

Como usar

  • Escolher um valor (ou todos) no seletor.
  • Expandir um valor para ver as regras; expandir uma regra para ver a condição completa.
  • Seguir para as propriedades afetadas, para as fichas das regras e para a vista de decisão.
  • Seletor de valor: mostra só o fluxo de um valor.
  • Resumo: matriz valor × propriedade afetada, com o número de regras que passam a aplicar-se.

dependencias: Análise de dependência de validade

  • Pergunta. Que restrições e conclusões implica cada valor desta propriedade, e que propriedades dependem dela?
  • Tese. Figura "Propriedades cuja restrição é inferida a partir de tipoDispositivo".
  • Parâmetros. propriedade (chave).
  • Operação sobre o grafo.
    1. (p)<-[:TERMO]-(Condicao)<-[:CONDICIONADA_POR]-(Regra) e (p)<-[:LE {parte: termo}]-(Funcao) (regras cuja condição lê a propriedade).
    2. De cada regra, a condição completa (todos os termos, com o termo sobre p marcado foco) e os alvos: -[:RESTRITA_POR]->(Restricao)-[:RESTRINGE]-> ou -[:CHAMA]->(Funcao)-[:LE]->.
    3. Os valores: as RP IN de p (plausíveis) e os valores usados nos termos de seleção. Para cada valor, as regras cujos termos de foco (EQUALS, IN, NOT_EQUALS) são verdadeiros com esse valor.
  • JSON. propriedade, plausiveis[], rp[], valores[] = {valor, plausivel, regras[], afetadas[], semRegras}, outrosTermos[] (regras cujo termo não é de seleção), regras[] (fichas, com foco em cada termo e alvos[]), afetadas[].
  • Cypher. dependencias.cypher.

Consulta Cypher equivalente (dependencias.cypher)

// ViewModel 'dependencias' — que restrições e conclusões implica cada valor desta propriedade?
// Parâmetros: $propriedade (chave, ex.: "SM:Identificacao.tipoDispositivo").

// 1. Valores plausíveis (RP com IN que vivem na propriedade)
MATCH (p:Propriedade {chave: $propriedade})<-[:ASSOCIADA_A]-(:RP)-[:RESTRITA_POR]->(rs:Restricao {operador: 'IN'})
RETURN rs.valor AS plausiveis;

// 2. Cada regra cuja condição lê a propriedade: o termo de foco, a condição completa e os alvos
MATCH (p:Propriedade {chave: $propriedade})<-[t:TERMO]-(c:CondicaoAplicabilidade)<-[:CONDICIONADA_POR]-(r:Regra)
OPTIONAL MATCH (r)-[:RESTRITA_POR]->(rs:Restricao)
OPTIONAL MATCH (rs)-[:RESTRINGE]->(alvo:Propriedade)
OPTIONAL MATCH (rs)-[:CHAMA]->(:Funcao)-[le:LE]->(arg) WHERE le.regra = r.id
RETURN r.id AS regra, [l IN labels(r) WHERE l <> 'Regra'][0] AS tipo, t.operador AS operador, t.valor AS valor,
       t.texto AS termoFoco, c.descricao AS condicao, rs.descricao AS restricao, coalesce(rs.mensagem, r.mensagem) AS mensagem,
       collect(DISTINCT alvo.chave) + collect(DISTINCT coalesce(arg.chave, arg.nome)) AS alvos, r.conclusaoValor AS conclusao
ORDER BY tipo, regra;
