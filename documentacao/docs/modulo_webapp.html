ecv/7_webapp/__init__.py

7 · Web application: every operation of modules 0 to 6 on a page, without the command line.

Receives: HTTP requests from the browser (pages and forms) or from scripts (/api/...).
Needs: the workspace (dominios/), the GraphDatabase of the active scope (memory or Neo4j) and the request
queues to the LLM.
Produces: pages and JSON; the actions change the domain's files through modules 0, 1, 2 and 6 (never directly).

    routes.py       the table of endpoints (method, path, handler, description)
    server.py       router, logging and errors around the handlers; serve()
    http.py         Request and Response
    context.py      AppContext: workspace, database, active scope, view catalogue
    logs.py         the server log (console, registos/servidor.log, the Registo tab)
    pages/          layout (tabs, scope selector) and HTML components
    handlers/       one module per tab: home, inventory, builder, amendments, requests, functions, database, views, validation

    python -m ecv servidor [--neo4j] [--ambito <dominio>] [--porta 8000]

(sem definições públicas)

ecv/7_webapp/handlers/amendments.py

Alterações (module 2): the review of the declarations, layer by layer (A to F).

Each layer shows, from top to bottom:
    operations     the operations of the layer; choosing one opens its guided form
    guided form    selectors with what exists (model, property, rule, projection, ...), the context for the decision
                   (plausible values, links to the analysis views) and the operation already filled in (JSON), to preview
                   and apply; a projection is chosen with checkboxes over the HLM's paths
    what exists    the entities of the layer, each with a link to change it
Two more sub-tabs: CSV (a table of known mappings becomes one RIR per row) and the vocabulary.
Where everything lives in the code and in the files is shown on each page.

ecv/7_webapp/handlers/functions.py

Funções: what a function needs in each module.

    declared      in a declaration (name, parameters, external contexts, meaning) — module 2, operation definir_funcao,
                  or a step response (step E); it is part of the graph
    implemented   in Python, in ecv/6_validation/functions — needed to evaluate the rules that call it
A declared function without implementation makes its rules 'não avaliável'. The implementation is asked
to the LLM as a request of the global queue; registering the response installs the module.

ecv/7_webapp/handlers/requests.py

Pedidos ao LLM: the queues of requests (one per domain, plus the global queue for function implementations),
each request with its prompt, its response and what was done with it.

How a request is answered (shared/llm_requests.py):
    1. in the repository: the LLM reads <pasta>/prompt.md and writes <pasta>/resposta.json (or resposta.py) and commits;
       after a pull the request shows as 'respondido';
    2. here: copy the prompt to an LLM and paste the response below.
Then 'Registar' applies the response (module 1 for steps and changes, module 6 for functions).

ecv/7_webapp/server.py

The HTTP server: routing, logging and error handling around the handlers.

Each request: the AppContext refreshes the database if the declaration files changed, the router finds
the route (routes.py), the handler returns a Response, and one line goes to the log. Errors the user
can fix (EcvError, HttpError) become a page or a JSON {"erro": ...}; anything else is logged with
its traceback and answered with 500.
