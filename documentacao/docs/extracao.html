Extração e inventário

Como cada fonte, no seu formato, passa ao formato intermédio de onde parte a geração, e como se escreve um adaptador.

Porque há um formato intermédio

As fontes de um domínio vêm em formatos muito diferentes: um PDF com tabelas, ficheiros schematron com asserções XPath, XML anotado, classes Dart, uma folha de cálculo, JSON Schema. Dar ao LLM os ficheiros em bruto teria três problemas:

  • o LLM teria de conhecer cada formato;
  • os pormenores da sintaxe (namespaces, XPath, anotações Dart) ocupariam o contexto sem acrescentar significado;
  • não haveria forma de confirmar que cada informação da fonte foi tratada.

Por isso, antes da declaração há um formato intermédio, o inventário. Cada fonte é convertida nele por um adaptador: um programa que sabe ler aquele formato concreto e só escreve o que a fonte significa. Esse conteúdo são os grupos de informação, os campos com o seu tipo, a cardinalidade e a descrição, e as regras. O inventário é igual para todas as fontes, e é dele que parte a geração das declarações.

Como é criado

  1. O dominio.json do domínio lista as fontes. Cada fonte tem um id, o nome do adaptador e o caminho dentro de data/.
  2. A extração (Declaração › 1. Extração, ou python -m ecv inventario extrair <d>) faz, para cada fonte:
    • encontra o ficheiro;
    • chama o adaptador registado em ecv/0_transformer/adapters/__init__.py (ADAPTERS);
    • grava o resultado em dominios/<d>/inventario/<id>.json.
  3. O adaptador constrói um Inventory (ecv/0_transformer/inventory.py) com três listas: grupos (Group), elementos (Element) e regras (SourceRule).
    • Um tipo da fonte reconhecido passa ao tipo base da ECV (base_type).
    • Cada regra é classificada numa categoria, a partir do texto e da expressão (classify).
    • Cada item guarda a sua origem: o ficheiro e a localização na fonte.
  4. A fase 0 fica em revisão; os inventários revêem-se no separador Inventário e a extração é aceite em Declaração › 1. Extração.

O inventário ainda não é ECM. Os grupos são os da fonte (um BG do CIUS-PT, um registo do FM, uma classe Dart) e não têm de corresponder a submodelos. É a geração que decide a estrutura ECM a partir dos grupos e elementos de todas as fontes. Nessa decisão junta o que significa o mesmo e decompõe o que mistura conceitos.

O formato do inventário

{
 "fonte":     {"id": "fm-registos", "nome": "Desenho dos registos de exportação FM", "tipo": "…", "adaptador": "fm.registos", "caminho": "data/FM/…"},
 "grupos":    [{"id": "VDM", "nome": "Vendedores e Numerações", "pai": null, "cardinalidade": null,
               "elementos": ["VDM.Codigo Vendedor", "…"], "origem": "…: registo VDM"}],
 "elementos": [{"id": "VDM.Codigo Vendedor", "nome": "Codigo Vendedor", "descricao": "…", "tipo": "inteiro", "tipoOrigem": "N",
               "cardinalidade": null, "grupo": "VDM", "nomesAlternativos": [], "valoresAdmitidos": null, "notas": "comprimento 10", "origem": "…"}],
 "regras":    [{"id": "VDM-2-COMPRIMENTO", "texto": "…", "categoria": "formato", "natureza": "RP", "gravidade": "erro",
               "elementos": ["VDM.Codigo Vendedor"], "expressao": "…", "origem": "…"}]
}

A categoria de cada regra indica a camada que a revê (e cuja cobertura a exige):

  • presença e cardinalidade: camada B (projeções);
  • formato, valores e gama: camada C (plausibilidade);
  • condicional, exclusão e outra: camada D (inferência);
  • cálculo e cruzada: camada E (funções).

A natureza (RE, RP, RIR, FN) é só uma sugestão. O passo decide.

Como escrever um adaptador para um formato novo

  1. Criar ecv/0_transformer/adapters/<formato>.py com uma função que recebe o caminho da fonte e devolve um Inventory:
from pathlib import Path

from ecv.transformer.classification import base_type, classify
from ecv.transformer.inventory import Element, Group, Inventory, SourceRule


def read(path):
    inventory = Inventory({"nome": "…", "tipo": "…", "ficheiro": Path(path).name, "adaptador": "formato.read"})
    # each set of fields of the source:
    inventory.groups.append(Group(id="G1", name="…", elements=["G1.campo"], origin="…"))
    # each field:
    inventory.elements.append(Element(id="G1.campo", name="…", description="…", type=base_type("…"), cardinality="0..1",
                                      group="G1", origin="…"))
    # each rule the source declares:
    category, nature = classify(text, expression)
    inventory.rules.append(SourceRule(id="R1", text=text, category=category, nature=nature, elements=["G1.campo"],
                                      expression=expression, origin="…"))
    return inventory
  1. Registá-la em ADAPTERS ("formato.read": formato.read).
  2. Acrescentar a fonte ao dominio.json com "adaptador": "formato.read".
  3. Extrair (Declaração › 1. Extração) e rever no separador Inventário. Um formato sem adaptador pode ser pedido ao LLM no mesmo sítio.

O adaptador não interpreta nem decide. Lê e normaliza os nomes, os tipos, as cardinalidades, o texto das regras e a origem. As decisões de modelação são da geração e são revistas por camadas.

Um formato sem adaptador

Em Declaração › 1. Extração, ao acrescentar uma fonte, a opção "não existe: pedir a criação de um adaptador" (ou o formulário Pedir um adaptador novo) cria um pedido ao LLM na fila global. O prompt (ecv/0_transformer/prompts/criar_adaptador.md) leva a descrição do formato, uma amostra do ficheiro, o código do formato do inventário, as categorias das regras e um adaptador existente como exemplo. Registar a resposta (ecv/0_transformer/adapter_requests.py) confirma que o módulo compila e define NAME e adapt(path), grava-o em adapters/a_<nome>.py, recarrega o registo e corre-o na amostra; se falhar, o módulo anterior é reposto.

Texto em linguagem natural

O adaptador texto.markdown lê uma descrição escrita por uma pessoa: cada secção ## Nome é um grupo, cada item - nome (tipo, obrigatório): descrição. Valores: A, B é um elemento, e cada frase com uma obrigação ou condição ("deve", "tem de", "só", "se", "no máximo"…) é uma regra candidata. O texto completo segue no prompt da geração. Exemplo: dados_teste/biblioteca/descricao_biblioteca.md (domínio biblioteca).
