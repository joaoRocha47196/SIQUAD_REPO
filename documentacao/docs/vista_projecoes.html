Matriz de projeções

As regras estruturais (RE) de um HLM: para cada propriedade (em cada caminho) e cada projeção, se é obrigatória, permitida ou excluída; e, para cada perfil que usa as projeções, os valores fixados.

CampoValor
Páginaprojecoes_<HLM>
ViewModelprojecoes
Para que serveComparar utilizações do mesmo HLM (ex.: fatura simplificada vs. comunicação à AT) e ver onde diferem.
Exemploprojecoes_Dispositivo.html (estática) · na aplicação: /vistas/projecoes_Dispositivo.html

Dados que agrega

  • as projeções do HLM e as propriedades obrigatórias e permitidas de cada uma (com '*' já expandido)
  • os perfis que usam cada projeção e o que fixam (propriedades e contextos externos)

Como usar

  • As linhas sombreadas são as propriedades em que as projeções diferem.
  • Seguir para a vista de cada perfil.

projecoes: Matriz de projeções

  • Pergunta. Que propriedades cada projeção exige ou permite, e o que fixa cada perfil?
  • Tese. Figura "Modelos Fatura e Dispositivo e respetivas projeções"; Tabela "Matriz de projeções do HLM Dispositivo".
  • Parâmetros. hlm.
  • Operação.
    1. Do HLM, <-[:PROJETA]- (projeções).
    2. De cada projeção, -[:OBRIGATORIA|PERMITIDA {caminho}]-> (marcas por caminho).
    3. Os caminhos de todas as propriedades vêm da árvore do HLM; um caminho sem marca está excluído.
    4. Perfis: <-[:USA]- da projeção e -[:FIXA]-> do perfil.
  • JSON. projecoes[]; linhas[] = {caminho, celulas{projecao: O|P|-}, difere}; perfis[] = {perfil, projecao, fixa[{caminho, valor, projetada} | {contexto, valor}]}.
  • Cypher. projecoes.cypher.

Consulta Cypher equivalente (projecoes.cypher)

// ViewModel 'projecoes' — matriz de projeções de um HLM e valores fixados pelos perfis.
// Parâmetros: $hlm (ex.: "Dispositivo").

// 1. Para cada caminho de propriedade, a marca em cada projeção (OBRIGATORIA / PERMITIDA; ausente = excluída)
MATCH (h:HLM {nome: $hlm})<-[:PROJETA]-(pj:Projecao)-[r:OBRIGATORIA|PERMITIDA]->(p:Propriedade)
RETURN r.caminho AS caminho, collect({projecao: pj.nome, marca: type(r)}) AS celulas
ORDER BY caminho;

// 2. Perfis que usam as projeções do HLM e o que fixam
MATCH (h:HLM {nome: $hlm})<-[:PROJETA]-(pj:Projecao)<-[:USA]-(pf:Perfil)
OPTIONAL MATCH (pf)-[f:FIXA]->(x)
RETURN pf.nome AS perfil, pj.nome AS projecao,
       [i IN collect({alvo: coalesce(f.caminho, x.nome), tipo: labels(x)[0], valor: f.valor}) WHERE i.alvo IS NOT NULL] AS fixa
ORDER BY perfil;
