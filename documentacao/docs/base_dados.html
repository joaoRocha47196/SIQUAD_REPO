Base de dados da aplicação

O que suporta a aplicação web: as declarações ingeridas num grafo, em memória ou no Neo4j, reconstruído quando os ficheiros mudam.
Recebe
um âmbito: o nome e a lista dos seus ficheiros de declaração
Precisa de
o backend (memória ou Neo4j, com as credenciais da configuração)
Produz
o grafo do âmbito, que as consultas leem pela interface Graph, e o estado (ficheiros, declarações aceites e rejeitadas, contagens)

A base de dados da aplicação web é o grafo das declarações do âmbito ativo. Os ficheiros são a fonte de verdade; a base de dados existe para as consultas. A cada pedido, a aplicação compara a impressão digital dos ficheiros do âmbito (caminhos e datas de modificação) com a da última construção; se mudou, ingere de novo. Uma alteração feita pelos passos ou pelas alterações aparece, por isso, no pedido seguinte.

  • memória: o grafo vive no processo do servidor; não precisa de nada instalado.
  • neo4j (python -m ecv servidor --neo4j): a cada construção, os nós ECV são apagados e o grafo é carregado em lotes; as vistas e a validação leem o Neo4j (Neo4jGraph) e as consultas Cypher equivalentes podem correr-se no Neo4j Browser.

O âmbito escolhe-se no topo de cada página da aplicação. A pré-visualização da fusão (separador Base de dados) compara uma declaração colada com o grafo do âmbito sem escrever nada: uma declaração só passa a fazer parte da base de dados quando é um ficheiro do âmbito.

Interface (ecv/4_graph/database.py)

GraphDatabase: the database behind the web application.

The declaration files are the source of truth. The database is the graph they become once ingested,
kept for queries: every view, validation and search reads it through the Graph interface.

    declaration files ──ingest (module 3)──▶ MemoryGraph ──(backend neo4j)──▶ Neo4j
          (scope)                              │                                  │
                                               └──────────── Graph interface ─────┘──▶ views, validation, search

A scope is a named set of declaration files: the example declarations, or the declarations of one
domain. The database holds one scope at a time and is rebuilt when the files of the scope change
(their paths and modification times form the fingerprint), so a change applied by the builder or
the amendments module is visible in the next request.

Backends:
    memoria   the graph lives in the server process (no dependencies)
    neo4j     the graph is written to Neo4j (cleared and loaded on each rebuild) and queried with Cypher;
              the views can then also be run as Cypher (module 5, viewmodels/cypher)
