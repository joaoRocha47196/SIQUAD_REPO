Documentação técnica da ECV de referência

O que o sistema faz, como está dividido em módulos, onde estão os dados e como se instala.

O sistema

O ecv_referencia é a implementação de referência da Estratificação do Conhecimento de Validação (ECV). A ECV descreve num formato único o que um dado tem de cumprir para ser válido: a ECM descreve a estrutura (HLM, SM, USM, propriedades e composições) e a ECR descreve as regras (estruturais, através das projeções; de plausibilidade, RP; de inferência, RIR e RIC; funções, contextos externos e perfis). Cada HLM é descrito por uma Declaração ECV, um ficheiro JSON.

O código está dividido em oito módulos numerados pela ordem em que os dados passam por eles:

Cada caixa abre a página do componente. Setas a cheio: o caminho dos dados. Tracejado: a especificação entra em cada prompt; a aplicação web aciona os módulos 1 e 2.

MóduloRecebeProduz
0 · transformerficheiros de origem em formatos conhecidos (PDF, schematron, XML UBL, Dart, xlsx, JSON Schema)um inventário por fonte: grupos, elementos e regras, com a origem de cada item
1 · ecv_builderos inventários de um domínio e a especificação internaas declarações completas do domínio, geradas num só pedido ao LLM e revistas por camadas (A a F)
2 · amendmentsoperações de um vocabulário fechado (de uma resposta do LLM, de um formulário ou de uma tabela CSV)as declarações alteradas de forma consistente
3 · ingestiondeclaraçõeso grafo integrado, verificado e sem duplicados
4 · grapho grafo materializadoo armazenamento (memória ou Neo4j) e a interface de leitura comum
5 · viewso grafo e o nome de uma vista com os seus parâmetroso ViewModel (JSON) e a página HTML
6 · validationo grafo, uma instância de um HLM e um perfilo resultado da validação de cada regra em cada ocorrência
7 · webapppedidos HTTPas páginas e a API que dão acesso a todas as operações dos módulos 0 a 6

Os pacotes de apoio são config (a configuração única), shared (a área de trabalho dos domínios e a troca de pedidos com o LLM) e tools (este gerador de documentação).

Onde estão os dados

Os ficheiros são a fonte de verdade e estão versionados no repositório:

FicheiroConteúdo
specs/a especificação (uma página por entidade), a estrutura e o esquema da declaração, as declarações de exemplo
dominios/<d>/dominio.jsonas fontes do domínio, as exclusões, as utilizações e os cenários
dominios/<d>/inventario/*.jsonos inventários (módulo 0)
dominios/<d>/declaracoes/*.ecv.jsonas declarações do domínio, uma por HLM (módulos 1 e 2)
dominios/<d>/mapeamento.jsono destino de cada elemento e de cada regra das fontes, ou o motivo do descarte
dominios/<d>/estado.jsono estado da fase 0, da geração (G) e das camadas de revisão (A a F)
dominios/<d>/pedidos/ e pedidos/os pedidos ao LLM e as respostas

O grafo é derivado dos ficheiros. A ingestão (módulo 3) verifica cada declaração e funde-a com as anteriores, de modo que os modelos, as regras e as funções partilhados por várias declarações ficam uma só vez. Todas as consultas (vistas, validação e pesquisa) leem o grafo. O grafo não se edita diretamente: uma alteração é feita nos ficheiros, pelos módulos 1 e 2, e o grafo é reconstruído.

A base de dados da aplicação web é o grafo do âmbito ativo: as declarações de exemplo ou as declarações de um domínio. Vive em memória ou no Neo4j (--neo4j). É reconstruída quando os ficheiros do âmbito mudam e, no Neo4j, é limpa e carregada de novo. Ver Base de dados.

O LLM

Nenhum módulo chama um LLM. Cada tarefa que precisa de um (um passo da declaração, um pedido de alterações em linguagem natural, a implementação de uma função) passa a ser um pedido: uma pasta com o prompt completo, onde a resposta é escrita. A resposta pode ser escrita no repositório (e enviada com commit) ou colada na aplicação web. O código confirma a forma da resposta e aplica-a de forma determinística. Ver Pedidos ao LLM.

Instalação

Python 3.10 ou superior. O núcleo só usa a biblioteca padrão; os pacotes de requirements.txt são opcionais (jsonschema para a verificação contra o JSON Schema, neo4j para o Neo4j). Para voltar a extrair o guia CIUS-PT (PDF) é precisa a ferramenta pdftotext.

cd ecv_referencia
pip install -r requirements.txt
python -m unittest discover -s tests -t .
python -m ecv servidor                    # http://127.0.0.1:8000

Neo4j (opcional):

docker run -d --name ecv-neo4j -p 7474:7474 -p 7687:7687 -e NEO4J_AUTH=neo4j/ecvreferencia neo4j:5.26-community
python -m ecv servidor --neo4j
NEO4J_URI=bolt://localhost:7687 python -m unittest discover -s tests -t .

As credenciais estão em ecv/config/ecv.config.json (secção neo4j); as variáveis NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD e NEO4J_DATABASE substituem-nas.

Linha de comandos

A aplicação web faz todas as operações; a linha de comandos faz as mesmas, para scripts e testes.

ComandoO que faz

python -m ecv descricoes [--escrever] declaracaoderiva as descrições das regras
python -m ecv grafo [--cypher CYPHER] [declaracoes ...]ingere em memória, conformidade, exporta Cypher
python -m ecv importar [--limpar] [declaracoes ...]ingere no Neo4j (só o que é novo)
python -m ecv vm [--neo4j] nome [argumentos ...]um ViewModel em JSON
python -m ecv cypher nome [parametros ...]a consulta Cypher equivalente a um ViewModel, no Neo4j

python -m ecv validar [--perfil PERFIL] [--hlm HLM] [--contexto [CONTEXTO ...]] [--neo4j] instancia [declaracoes ...]valida uma instância contra as regras
