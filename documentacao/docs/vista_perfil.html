Perfil de execução: seleção estática

O que um perfil resolve antes da execução: com a projeção e os valores fixados (propriedades e contextos externos), cada regra do HLM fica sempre aplicável, nunca aplicável, dinâmica ou não avaliável.

Para que serveConfirmar que um perfil faz o que se pretende e encontrar regras que não podem ser avaliadas.

Dados que agrega

  • a projeção, as propriedades e os contextos fixados
  • cada regra (em cada ocorrência), o estado de cada termo e o estado da regra

Como usar

  • Ler as regras por estado; seguir para a ficha de cada uma.

perfil: Seleção estática e dinâmica

  • Pergunta. Que regras o perfil torna sempre aplicáveis, nunca aplicáveis, dinâmicas ou não avaliáveis?
  • Tese. Figuras "Seleção estática" e "Propriedade usada na aplicabilidade mas não projetada".
  • Parâmetros. perfil.
  • Operação.
    1. (Perfil)-[:USA]->(Projecao)-[:PROJETA]->(HLM).
    2. Os caminhos projetados (-[:OBRIGATORIA|PERMITIDA]->) e os valores fixados ((Perfil)-[:FIXA]->).
    3. Para cada regra da árvore do HLM, em cada ocorrência (prefixo), cada TERMO é classificado:
    4. verdadeiro/falso se o caminho absoluto está fixado (avaliado com ecv/5_views/viewmodels/evaluation.py);
    5. dinâmico se está projetado;
    6. indisponível se não está projetado nem fixado.

Um termo com função é dinâmico se todos os argumentos estão disponíveis.

  • Estado da regra. nunca aplicável (um termo falso), alvo fora da projeção, não avaliável (um termo indisponível), sempre aplicável (todos verdadeiros) ou dinâmica. As RP ficam avaliada ou fora da projeção. Os contextos externos ficam "fixado no perfil" ou "obtido pelo motor".
  • JSON. projecao, hlm, fixados[] {caminho, valor, projetada}, contextos[] {nome, valor}, resumo {estado: n}, regras[] {regra, tipo, ocorrencia, descricao, estado, termos[{texto, estado, caminhos, valorFixado}], alvos, contextos, restricao}.
  • Cypher. perfil.cypher (estado de cada termo; EQUALS resolvido em Cypher, os restantes operadores no Python).

Consulta Cypher equivalente (perfil.cypher)

// ViewModel 'perfil' — seleção estática: estado de cada termo das condições face aos valores fixados no perfil.
// Parâmetros: $perfil (ex.: "RefrigeracaoLote").
// Termo: verdadeiro/falso (EQUALS resolvido pelo valor fixado), dinâmico (propriedade projetada), indisponível.
// A classificação completa (todos os operadores, estado da regra) está em vistas/viewmodels/perfis.py.
MATCH (pf:Perfil {nome: $perfil})-[:USA]->(pj:Projecao)-[:PROJETA]->(h:HLM)
OPTIONAL MATCH (pf)-[f:FIXA]->(:Propriedade)
WITH pj, h, collect({caminho: f.caminho, valor: f.valor}) AS fixados
MATCH caminho = (h)-[:COMPOSTO_POR*0..2]->(m)
WITH pj, fixados, m, reduce(s = '', r IN relationships(caminho) | s + CASE s WHEN '' THEN '' ELSE '.' END + r.papel) AS prefixo
OPTIONAL MATCH (m)-[:CONTEM]->(prop:Propriedade)
WITH pj, fixados, prefixo, m, collect(prop) AS props
UNWIND [m] + props AS no
MATCH (r:Regra)-[:ASSOCIADA_A]->(no)
MATCH (r)-[:CONDICIONADA_POR]->(:CondicaoAplicabilidade)-[t:TERMO]->(:Propriedade)
WITH pj, fixados, r, t, CASE prefixo WHEN '' THEN t.caminho ELSE prefixo + '.' + t.caminho END AS absoluto
WITH pj, r, t, absoluto, [x IN fixados WHERE x.caminho = absoluto | x.valor][0] AS fixado
OPTIONAL MATCH (pj)-[o:OBRIGATORIA|PERMITIDA {caminho: absoluto}]->()
RETURN r.id AS regra, t.texto AS termo, absoluto AS caminho, fixado,
       CASE WHEN fixado IS NOT NULL THEN
              CASE WHEN t.operador = 'EQUALS' THEN CASE WHEN fixado = t.valor THEN 'verdadeiro' ELSE 'falso' END
                   ELSE 'resolvido pelo perfil' END
            WHEN o IS NOT NULL THEN 'dinâmico'
            ELSE 'indisponível' END AS estado
ORDER BY regra, caminho;
